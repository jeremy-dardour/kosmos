Seven working sessions on branch `auth-v1.1`, merged into one entry: planning

session restore), implementing it, two review passes, the sign-in button bug, and

## What shipped

- **`GET /api/users/me`** — auth-guarded, verifies the Google token, checks
  `AUTH_ALLOWED_EMAILS`, provisions the `User`, returns `CurrentUserDto`
  (`id`, `email`, `name`, `avatarUrl`). E2E covers `200` / `401` / `403`.
- **Backend-validated web sessions.** Web state becomes authenticated only after
  `/users/me` succeeds; rendered identity comes from the server, never from
  client-decoded Google claims (those are used for expiry only).
- **Fixed the empty sign-in button** — the button rendered, then its own cleanup
  deleted it (`container.replaceChildren()` under StrictMode's double-invoked
  effect wiped the second call's node).
- **Unauthenticated landing** rewritten: no GIS prompt on load, no hardcoded
  filler, all strings in i18next (`auth.landing.*`, en/fr/es).
- **`AuthSystem` composes the complete auth module** — a four-member
  `AuthSession` for restoration, state, tokens, and logout plus the
  provider-bound `SignInButton` for identity acquisition. Google uses only the
  official GIS rendered button; the One Tap prompt state machine was deleted.
  `AuthProviderBoundary`, both `useReducer` rerender counters, `AuthViewState`,
  and `restore()` remain deleted. `@/testing/stub-auth` covers the composed
  system.
- **Stale validation cannot recreate or overwrite sessions.** Credential
  validation is operation-scoped; logout and newer credentials invalidate
  older `/users/me` work before it can mutate state or storage.

All boundaries and their rationale are in
[ADR 0007](../adr/0007-web-auth-module-boundaries.md) — not repeated here. It
supersedes the frontend-flow steps in
[V1 Tech Design § Auth](../specs/v1-tech-design.md#auth).

## Decisions not carried by the ADR

- **Backend stays stateless**: no server session, no refresh-token storage. The
  short-lived Google ID token lives in **`sessionStorage`** — refresh in the same
  tab works, persistence ends with the tab.
- **Fake auth's purpose is narrow**: make web + API e2e-testable without Google.
  Multi-user dev switching, moving the allow-list into `MockAuthStrategy`, and
  MSW were each considered and rejected as solving problems this project doesn't
  have.
- The interface redesign **landed on `auth-v1.1` rather than after it** — PR #32
  was not reviewable with the old surface or the parallel One Tap flow.

## Durable learnings

**Design**

- **A wide interface propagates into everything around it.** Five spec files each
  hand-built the same 11-field literal, and `AuthProviderBoundary` existed only
  because it had 11 methods to forward. Fixing the interface deleted the
  component and the literals; neither needed simplifying on its own. When a
  helper exists to absorb an interface's width, fix the interface.
- **`restore()` was the clearest leaky signature seen so far**: `void |
Promise<void>` hid four facts that lived elsewhere (check `isAuthenticated()`
  after; throws on some failures, returns quietly on others; safe to call twice;
  differs from `login()` only by the prompt). Deleting the method deleted the
  facts.
- **Capabilities with incompatible shapes should be composed, not forced into
  one command interface.** Fake auth can sign in imperatively; reliable GIS
  sign-in is provider-owned UI. `AuthSystem` places `AuthSession` beside its
  bound `SignInButton` without making the fake implement Google's DOM lifecycle
  or making Google pretend its button is an imperative `signIn()`.

**React**

- **Memoizing a context value can silently break propagation.** Tried it as an
  optimisation on the auth boundary; context compares by reference, so a stable
  object meant consumers never re-rendered. Two tests caught it. Inviting-looking
  change, no type error.
- `useSyncExternalStore` loops unless `getState()` returns a stable reference
  until the state actually changes.
- A component type in context must be created once at the composition root. A
  component type created by a hook during render is new on every pass and resets
  its state (`react-hooks/static-components`); the stable
  `AuthSystem.SignInButton` does not.

**Process**

- **Diagnose from evidence before proposing a fix.** Session 18 proposed a
  loading state and a failure fallback for the empty button, assuming GIS was
  slow or throwing. It resolved successfully every time — the fallback was
  unreachable and a spinner would have shown the same empty box. The network
  panel had the answer (two `gsi/button` iframes, both `ERR_ABORTED`) and was not
  opened.
- **A fresh parallel workspace has an empty dev database** — the setup script
  provisions ports, not schema. Symptom is a `500` from anything touching the DB,
  auth included. Run `pnpm --filter api db:migrate:up` before suspecting code.
- Vitest/Supertest and Playwright need **unsandboxed** execution to bind local
  ports; `pnpm generate:api-types` needs a running API (start it with
  `FAKE_AUTH=true` to skip OIDC discovery).
- Playwright MCP installed (user scope) — used to confirm the landing page in a
  real browser, which is what caught the button bug.

## Review round

A line-by-line pass on PR #32 produced ~30 comments. Three were defects rather
than taste:

- **`signOut(reason?: AuthError)` was inert and divergent.** The only caller
  passing a reason was the 401 middleware, and its `token_rejected` mapped to
  the same `anonymous` a bare `signOut()` produces — while `FakeAuthProvider`
  mapped the identical argument to `error`. Dropped the parameter.
- **The provider's optional `{ validateToken, storage, now }` bag was dead** —
  no call site, test or otherwise, ever passed it.
- **`loadScript` removed a GIS tag that was still loading** and appended a
  replacement, restarting the download and racing two copies. Now it awaits the
  pending tag; covered by a regression test verified to fail on the old code.

Also renamed the strategy interface `AuthProvider` → `Auth` (it is neither a
React context provider nor a session — it outlives every session and reports
`anonymous`; the concrete classes keep the `…AuthProvider` suffix as identity-
provider adapters), replaced the `{ provider, signInButton }` pair with a
`<SignInButton />` that branches on the concrete implementation, and extracted
`UnauthenticatedLanding`.

Session 21 revisited that intermediate design after reviewing
`GoogleAuthProvider`. The shared imperative `Auth.signIn()` was keeping a second
One Tap flow alive solely for retry/fallback paths. GIS prompt notifications,
credential callbacks, and a local timeout could settle independently, creating
false failures and late authentication. The final design replaces `Auth` with:

```ts
interface AuthSystem {
  session: AuthSession;
  SignInButton: React.ComponentType;
}
```

`createAuthSystem()` binds the fake or Google session to its matching sign-in
component once. `AuthContext` carries the stable system; `useAuth()` still
returns the session for existing consumers; `<SignInButton />` delegates without
an `instanceof` branch. Error states render the same provider affordance again,
and GIS script-load retry rerenders the official button rather than falling back
to One Tap.

**The comment standard was broken by the commit that introduced it.** Ten
comments duplicated ADR 0007's rationale into the code, which `STANDARDS.md §
Comments` — added earlier in this same PR — explicitly forbids. Writing a
standard and applying it are separate acts. The standard was then rewritten
mid-review to one blunt line ("DO NOT comment something that is self
explanatory in the code"), and every remaining comment re-audited against it:
what survives states a constraint the code cannot show.

Docs realigned with the shipped code rather than left describing the plan:
ADR 0007 carries the `AuthSystem` seam, button-only GIS flow, operation
generation, `signOut()` reasoning, and script-loading rule; the tech design's
auth follow-up keeps the API contract and cedes frontend structure to the ADR;
the original Auth PRD marks its One Tap implementation sketch as superseded;
`apps/web/STANDARDS.md § Auth` documents the current system. Ports moved out of
`CLAUDE.md` into [PORTS.md](../../PORTS.md).

Session 21 verification: `pnpm format:check`, `pnpm check-types`, `pnpm lint`,
and `pnpm test` all pass; repository tests total 77.
